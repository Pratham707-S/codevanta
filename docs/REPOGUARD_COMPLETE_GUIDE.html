CH 01 Project Overview

1.1 What is RepoGuard?

RepoGuard is a CLI-first, AI-assisted repository security and reliability platform built on Node.js and TypeScript. Designed with the core philosophy "Fix with evidence. Verify before trust," RepoGuard bridges the gap between passive code scanners (linters and static analysis) and automated remediation. It provides structured code audits, multi-format reporting (HTML, Markdown, JSON), persistent scan histories, and strict sandboxed verification workflows.

1.2 The Problem RepoGuard Solves

Modern software development teams face three acute challenges:

  • AI Code Hallucination: Generative AI tools frequently suggest syntax-plausible but fundamentally broken code patches, introducing subtle logic bugs or security regressions.
  • Noisy Alert Fatigue: Traditional static analysis tools generate hundreds of context-free warnings with no automated verification or concrete proof of exploitability.
  • Unsafe Automation: Automated fixing scripts frequently execute untrusted shell commands, expose secrets to cloud providers without sanitization, or modify production files without human approval gates.

RepoGuard was conceived to enforce evidence-backed repair: finding an issue, generating an audit timeline, validating repairs in isolated sandboxes, and presenting human-verifiable reports before any change reaches version control.

1.3 Target Audience

  • Application Security (AppSec) Engineers: Looking for standardized CLI tools to embed in CI/CD pipelines to enforce security baselines.
  • Full-Stack Developers: Needing quick, local code audits with instant visual reports in the browser without leaving the terminal.
  • Engineering Leads: Wanting auditable records of repository health and deterministic repair verification before merging PRs.

2.2 Architectural Layers & Clean Architecture Pattern

RepoGuard adheres to a Clean Architecture / Ports & Adapters design:

  • Presentation / CLI Layer (src/cli): Interacts with the user, parses arguments, controls process exit codes, and prints styled terminal feedback.
  • Application Core (src/application & Command Handlers): Coordinates use cases: loading config, requesting file ingestion, invoking persistence, and triggering reports.
  • Infrastructure Adapters (src/storage, src/report): Implements concrete persistence (file system JSON files) and output rendering (HTML templates, Markdown generators).
  • Domain Models (src/domain): Holds the canonical representations of findings, severities, run records, and evidence timelines.

3.1 CLI Entry Point: src/cli/cli.ts

The CLI entry point defines the root Commander instance, sets up global options, and handles lifecycle hooks: 

export function createCliProgram(version: string = '0.1.0'): Command {
  const program = new Command('repoguard');

  program
    .version(version, '-v, --version', 'Output the current version of RepoGuard')
    .description('Autonomous Code Reliability, Security & Verified Repair Platform 🛡️')
    .option('-c, --config ', 'Path to custom repoguard.config.json file')
    .option('--json', 'Output results in machine-readable JSON format')
    .option('--no-color', 'Disable terminal color output')
    .addHelpText('before', `
${getStaticBanner(version)}
`);

  // Register all CLI commands
  registerInitCommand(program);
  registerScanCommand(program);
  registerReportCommand(program);
  registerStatusCommand(program);

  // Hook to display animated startup effect on non-json, interactive terminal runs
  program.hook('preAction', async (_thisCommand, actionCommand) => {
    const opts = actionCommand.optsWithGlobals();
    const isJson = Boolean(opts['json'] || opts['format'] === 'json');
    if (!isJson && actionCommand.name() !== 'help') {
      await renderStartupEffect({ version });
    }
  });

  return program;
}
🔍 Line-by-Line Logic & Design Decisions:
  • Commander Factory Function: createCliProgram() returns a fresh Command instance rather than exporting a singleton. This enables Vitest test cases to instantiate isolated programs with clean arguments without side-effect pollution.
  • Global Options: Declared on the root program so they can precede or follow subcommands (e.g. repoguard --json scan and repoguard scan --json).
  • PreAction Banner Suppression: Notice const isJson = Boolean(opts['json'] || opts['format'] === 'json');. If JSON stdout is requested, the ASCII banner is suppressed immediately, ensuring that piping stdout into jq or JSON parsers produces no syntax errors.

3.3 Browser Launcher Safety & Windows Path Normalization: src/cli/formatter.ts

Launching a generated HTML report in the user's browser is an essential convenience (--open), but if implemented with shell-string concatenation (e.g., exec(`open ${path}`)), it introduces a critical Command Injection Vulnerability. 

export function toAbsolutePath(filePath: string): string {
  if (
    filePath.startsWith('/') ||
    /^[a-zA-Z]:[\/]/.test(filePath) ||
    posix.isAbsolute(filePath) ||
    win32.isAbsolute(filePath)
  ) {
    return filePath;
  }
  return resolve(process.cwd(), filePath);
}

export function getOpenCommand(
  filePath: string,
  platform: NodeJS.Platform = process.platform
): OpenCommandSpec {
  const absolutePath = toAbsolutePath(filePath);

  switch (platform) {
    case 'darwin':
      return { command: 'open', args: [absolutePath] };
    case 'win32':
      // On Windows, 'start' is a cmd.exe built-in command; passing discrete args avoids shell injection
      return { command: 'cmd.exe', args: ['/c', 'start', '""', absolutePath] };
    default:
      // Linux, FreeBSD, SunOS, etc.
      return { command: 'xdg-open', args: [absolutePath] };
  }
}

export function openInBrowser(
  filePath: string,
  platform: NodeJS.Platform = process.platform,
  spawnImpl: (command: string, args: string[], options?: object) => ChildProcess = spawn
): ChildProcess | undefined {
  const spec = getOpenCommand(filePath, platform);
  try {
    const child = spawnImpl(spec.command, spec.args, {
      detached: true,
      stdio: 'ignore',
    });
    if (child && typeof child.unref === 'function') {
      child.unref();
    }
    if (child && typeof child.on === 'function') {
      child.on('error', () => {
        // Prevent unhandled error event if the browser or binary is not found
      });
    }
    return child;
  } catch {
    return undefined;
  }
}
🛡️ Security & Cross-Platform Guarantees:
  • Zero Shell Interpolation: By passing discrete string arrays to spawn() without shell: true, arguments containing shell characters (like ; rm -rf / or $(whoami)) are treated as literal file paths by the operating system kernel.
  • Process Detachment (child.unref()): The CLI process does not hang waiting for the browser tab to close; it exits cleanly immediately.
  • Windows Drive Path Regex: /^[a-zA-Z]:[\/]/ recognizes Windows drive paths (such as C: eportsaudit.html) even when the test runner is executing on macOS or Linux, preventing accidental prepending of /Users/....

export function escapeHtml(unsafe: unknown): string {
  if (unsafe === null || unsafe === undefined) {
    return '';
  }
  const str = String(unsafe);
  return str
    .replace(/&/g, '&')
    .replace(//g, '>')
    .replace(/"/g, '"')
    .replace(/'/g, ''');

CH 05 Core Technical Concepts

1. Node.js ECMAScript Modules (ESM)

RepoGuard declares "type": "module" in package.json. This enables standard import/export syntax, top-level await, and requires explicit .js file extensions in relative imports (e.g. import { formatError } from '../formatter.js';).

2. TypeScript 5.8 & Strict Typings

Configured with "strict": true in tsconfig.json. We use as const assertions on tuple definitions (e.g. VALID_SCAN_FORMATS = ['summary', 'json', 'html', 'markdown'] as const) to derive exact string literal union types automatically: type ScanOutputFormat = (typeof VALID_SCAN_FORMATS)[number].

3. Commander.js & optsWithGlobals()

In Commander.js v13, calling cmd.opts() inside an action handler only returns options defined on that specific subcommand. When flags like --json or --config are defined on the parent program, calling cmd.optsWithGlobals<T>() is required to merge global options with command-specific options into a single typed object.

4. Non-Terminating Exit Codes (process.exitCode = 1)

Rather than calling process.exit(1) directly, RepoGuard assigns process.exitCode = 1. This allows pending asynchronous I/O and standard streams (stdout/stderr) to drain completely before the Node.js event loop terminates, and enables unit test runners (Vitest) to verify failures without having the test process forcibly killed.

5. XSS Defense & Safe HTML Escaping

User code and file paths are inherently untrusted. The escapeHtml() utility neutralizes dangerous characters (&, <, >, ", ') into their corresponding HTML entity equivalents. Furthermore, CSS class interpolation uses whitelist lookup maps to prevent attribute breakout.

git fetch origin

# 2. Switch to main and pull latest verified code
git switch main
git pull origin main

# 3. Create your new isolated feature branch
git switch -c feature/my-new-module

# 4. Make edits and run verification checks BEFORE committing
npm run typecheck
npm run lint
npm test
git diff --check

# 5. Push branch to GitHub and open a Pull Request
git push -u origin feature/my-new-module
🚫 Commands to NEVER Run on Shared Branches:
  • git push --force origin main: Destroys commits on the shared branch.
  • git reset --hard HEAD~1 (after pushing): Creates divergent histories and breaks teammates' local clones.

12.3 20+ Technical Q&A

Q1: Why did you use Commander.js instead of yargs or parsing process.argv manually?
Commander.js v13 provides a declarative API for nested subcommands, automated --help generation, typed option parsing, and lifecycle hooks like preAction which allow us to conditionally render ASCII banners or suppress them for JSON mode.
Q2: How does optsWithGlobals() work and why was it necessary?
In Commander, cmd.opts() only returns options declared directly on that subcommand. Because --json and --config are defined globally on the root program, subcommands like scan or status need cmd.optsWithGlobals() to inherit and merge both global and local flags.
Q3: What was the shell injection vulnerability in openInBrowser() and how did you resolve it?
Using string concatenation with child_process.exec(`open "${filePath}"`) permits shell metacharacter injection (such as ; rm -rf / or $(calc)). We resolved this by switching to child_process.spawn() with discrete string array arguments without invoking a shell.
Q4: Why does getOpenCommand on Windows use cmd.exe /c start ""?
On Windows, start is not a standalone executable; it is an internal shell command of cmd.exe. The empty quote pair "" is required because the Windows start command interprets the first quoted token as the window title.
Q5: How does toAbsolutePath handle Windows drive letters on non-Windows operating systems?
Standard POSIX path.isAbsolute('C:\test') returns false on macOS/Linux and prepends process.cwd(). We added a regex check /^[a-zA-Z]:[\/]/ to recognize Windows drive paths across all host platforms.
Q6: Why use process.exitCode = 1 instead of process.exit(1)?
process.exit() terminates the process immediately, truncating stdout/stderr buffers and preventing asynchronous cleanup. Setting process.exitCode = 1 lets the event loop drain naturally and allows test runners to assert on failure codes without dying.
Q7: How did you prevent Cross-Site Scripting (XSS) in HTML reports?
We implemented escapeHtml() to convert &, <, >, ", and ' into HTML entities. Furthermore, CSS class mapping uses predefined lookup objects rather than string interpolation, preventing attribute breakout attacks.
Q8: How does --format interact with the global --json flag?
--format governs which artifact is saved to disk (HTML, Markdown, or JSON), while --json guarantees machine-readable JSON on stdout. For instance, repoguard scan --format html --json generates an HTML file on disk while printing clean JSON to stdout.
Q9: What happens when an invalid format is passed to scan --format?
It validates the string against VALID_SCAN_FORMATS. If invalid, it logs a descriptive error message, sets process.exitCode = 1, and returns early without creating corrupted files.
Q10: What is the purpose of the RunStore and StateStore classes?
They provide file-backed storage in .repoguard/state/. RunStore archives complete audit run records under unique IDs, while StateStore tracks repository status and the last run ID.
Q11: How is configuration loaded in RepoGuard?
Via a cascading hierarchy: DEFAULT_CONFIG -> .repoguard/config.json -> Environment variables (REPOGUARD_*) -> CLI arguments (--config). All configurations are validated with Zod schemas.
Q12: Does the current scan command detect real vulnerabilities?
No. As documented in our honesty matrix, the current scan command counts files and creates a clean scan record. The static analysis rules and AI orchestrator are currently stubs.
Q13: Does the secret redactor actually redact tokens right now?
No. src/context/secret-redactor.ts is currently a stub. The progress step in the CLI terminal is cosmetic feedback planned for full integration in Milestone 2.
Q14: What testing framework is used and why?
Vitest 3.0.7 is used because it provides native ESM and TypeScript support without requiring a compilation step, executes fast in-memory, and provides full Jest-compatible mocking APIs.
Q15: How do your tests verify clean JSON stdout?
Tests spy on console.log, capture all output lines, join them, assert that the text contains no banner characters, and verify that JSON.parse(output) succeeds cleanly.
Q16: What is git diff --check and why did you run it?
git diff --check scans staged and unstaged diffs for trailing whitespace and conflict marker artifacts, ensuring code quality before committing.
Q17: Why use TypeScript interfaces instead of types for CLI options?
Interfaces support declaration merging and extension (e.g. interface ScanCommandOptions extends GlobalCliOptions), creating clean inheritance hierarchies for subcommand options.
Q18: What is the purpose of child.unref() in openInBrowser?
It removes the spawned child process from the Node.js event loop reference count, allowing the parent CLI process to exit immediately without waiting for the browser to close.
Q19: How does extractProjectName work across platforms?
It normalizes all backslashes to forward slashes with .replace(/\/g, '/') before calling path.basename(), ensuring proper project naming on both Windows and POSIX.
Q20: What is your next priority milestone for RepoGuard?
Connecting the CLI scan command to a real static analysis engine in src/analysis/orchestrator.ts and integrating regex-based secret redaction in src/context/secret-redactor.ts.
