# RepoGuard — AI Coding Rules & Architecture Constraints

This repository strictly enforces rules and constraints for all AI coding assistants working in RepoGuard.

---

## 1. Operating Rules
1. **Inspect Before Changing:** Read existing code, architectural rules, and shared domain contracts before creating or editing files.
2. **Modular Monolith Discipline:** Code must remain strictly within designated module boundaries:
   - `src/cli/` (Team Lead)
   - `src/application/` (Team Lead)
   - `src/domain/` (Team Lead, Manni, Pratham)
   - `src/repository/` (Manni)
   - `src/context/` (Manni)
   - `src/analysis/` (Team Lead)
   - `src/providers/` (Team Lead)
   - `src/repair/` (Pratham)
   - `src/verification/` (Pratham)
   - `src/report/` (Ayan)
   - `src/config/` (Ayan)
   - `src/storage/` (Ayan)
   - `src/utils/` (Team Lead)
   - `examples/` (Ayan)
3. **No Unilateral Contract Changes:** Shared domain schemas in `src/domain/` define contracts between team modules. Do not alter them without cross-team consensus.
4. **Zero Secrets in Prompts or Logs:** Sensitive tokens, `.env` files, certificates, and credentials must never be passed to AI providers or logged in output.
5. **No Direct Arbitrary Execution:** Never auto-execute arbitrary shell commands generated by models. All verification commands must follow explicit allowlists with strict timeouts.
6. **Explicit Approval Gate:** Patches and repository modifications require explicit interactive developer approval.
7. **Evidence-Driven Assertions:** A finding or repair status must be backed by concrete file/line evidence or actual test outcomes. Do not claim features work without test evidence.
